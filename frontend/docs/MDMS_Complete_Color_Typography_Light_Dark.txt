============================================================
1. PURPOSE
============================================================

This document defines the visual design system for an enterprise
Meter Data Management System (MDMS), including:

- Meter management
- Consumer management
- Head-end / AMI operations
- Load Survey (LS)
- Daily Load Profile (DLP)
- Validation, Estimation & Editing (VEE)
- Energy audit
- Revenue protection
- Prepaid engine
- Recharge and balance operations
- Billing-related data
- Reports and analytics
- System monitoring
- Operational dashboards

The design language should feel:

- Enterprise
- Reliable
- Technical
- Premium
- Calm
- Data-focused
- Highly readable
- Suitable for long operational sessions

PRIMARY UI STRATEGY:

LIGHT MODE:
Default working environment for most users.

DARK MODE:
Optional professional operating environment for users who
prefer dark interfaces or work in low-light environments.

Both modes use the same brand identity and semantic colors.
Only surface, text, border and interaction tokens change.

============================================================
2. CORE DESIGN PRINCIPLES
============================================================

1. Color communicates meaning.
2. Typography communicates hierarchy.
3. Spacing communicates structure.
4. Surface elevation communicates depth.
5. Semantic colors are reserved for operational meaning.
6. Avoid unnecessary visual noise.
7. Do not use color as the only status indicator.
8. Tables and operational data must remain highly readable.
9. Primary actions must be visually obvious.
10. Light and dark themes must feel like the same product.

The interface should NOT look like a generic admin dashboard.

It should look like a specialized energy operations platform.

============================================================
14. GRADE SYSTEM
============================================================

Grade changes perceived stroke density without substantially
changing layout.

Recommended:

Body:
Grade 0

Small text:
Grade 0 to slightly positive

Dark mode small text:
Slightly positive grade if needed for readability

Headings:
Grade 0

Large metrics:
Grade 0 to slightly positive

Do not use grade as a substitute for proper contrast.

============================================================
15. OPTICAL SIZE
============================================================

Use automatic optical sizing where supported:

font-optical-sizing: auto;

Concept:

Small text:
Optimize for text size.

Body:
Normal optical size.

Large headings:
Display optical treatment.

Optical size should support readability rather than become
a visible stylistic effect.

============================================================
28. TABLE DESIGN PRINCIPLES
============================================================

MDMS is a data-heavy system.

Tables must prioritize:
1. Readability
2. Scanability
3. Alignment
4. Status visibility
5. Density control

Recommended:
- 13px body text
- 12px headers
- 40-48px row height
- Mono font for technical identifiers
- Right-align numeric values
- Consistent decimal precision
- Status badges instead of full-row coloring

Avoid:
- Excessive row separators
- Huge typography
- Excessive colors
- Extremely dense rows
- Long unbroken text

36. ACCESSIBILITY
============================================================

The UI must not rely solely on color.

Example:

BAD:
Red = VEE failed

GOOD:
[!] VEE Failed

where:
- Red communicates severity
- Icon communicates state
- Text communicates exact meaning

Focus states must be obvious.

Light focus:
#0969DA

Dark focus:
#58A6FF

Avoid:
- Light gray text on white
- Dark gray text on dark navy
- Low-contrast disabled states
- Color-only charts
- Color-only status

============================================================

Dark mode should NOT simply invert the light theme.

Use a purpose-built dark hierarchy:

#06141B
    ↓
#11212D
    ↓
#253745
    ↓
#304553

The darker the surface, the lower its visual elevation.

Text:
#CCD0CF
    ↓
#9BA8AB
    ↓
#7F8D91

Do not use pure black #000000 as the main application
background.

============================================================
38. LIGHT MODE BEHAVIOR
============================================================

Light mode should remain mostly neutral.

Use:

#F5F7F8
    ↓
#FFFFFF
    ↓
#F1F4F5
    ↓
#E8EDF0

Primary text:
#11212D

Secondary:
#4A5C6A

Muted:
#6F7D83

The dark sidebar creates strong brand recognition while the
main content remains comfortable for long sessions.

============================================================
39. THEME SWITCHING
============================================================

The following elements should change between themes:

- Page background
- Header surface
- Cards
- Inputs
- Tables
- Borders
- Text colors
- Shadows
- Semantic soft backgrounds
- Focus treatment where required

The following should remain conceptually consistent:

- Font family
- Font sizes
- Font weights
- Spacing
- Border radius
- Component structure
- Semantic meaning
- Navigation structure
- Information hierarchy

Do NOT create separate component designs for light and dark.
Create one component system with theme tokens.

41. RECOMMENDED DEFAULT THEME
============================================================

Default:
LIGHT MODE

Reason:
MDMS contains:
- Large tables
- Long data sessions
- Meter records
- Consumer records
- Reports
- VEE results
- Load Survey data
- Audit information
- Revenue protection cases

Light mode is recommended for general operational work.

Dark mode should remain available for:
- Control room environments
- Low-light work
- User preference
- Monitoring dashboards
- Long sessions where users prefer dark surfaces

============================================================
43. DO / DON'T
============================================================

DO:

- Use Light Mode as the default.
- Keep the dark navy sidebar.
- Use Roboto Flex throughout the application.
- Use Roboto Mono for technical data.
- Use Noto Sans for multilingual fallback.
- Keep semantic colors consistent.
- Use subtle borders.
- Use whitespace.
- Use typography to establish hierarchy.
- Use surface elevation instead of excessive borders.
- Make tables highly readable.
- Keep charts restrained.
- Support a complete dark theme rather than simply inverting
  colors.

DON'T:

- Use pure black as the default background.
- Use pure white everywhere.
- Use 10+ bright colors in dashboards.
- Use color as the only status indicator.
- Make every card colorful.
- Make every navigation item bold.
- Use gradients as the main UI language.
- Use heavy shadows everywhere.
- Use different fonts for every module.
- Use too many font weights.
- Make technical IDs proportional when monospaced alignment
  is useful.
- Create separate inconsistent component designs for each theme.

============================================================
44. FINAL DESIGN PHILOSOPHY
============================================================

LIGHT MODE:

Clean.
Professional.
Operational.
Readable.
Data-first.

Dark navy sidebar + white content surfaces + restrained teal,
blue, green, amber and red status colors.

DARK MODE:

Technical.
Premium.
Focused.
Low-light friendly.
Data-first.

Deep navy background + slate surfaces + cool gray typography +
restrained semantic colors.

THE CORE SYSTEM:

Color = Meaning
Typography = Hierarchy
Spacing = Structure
Surface = Elevation
Icons = Recognition
Status = Action

The product should immediately communicate:

1. Where am I?
2. What is important?
3. What needs attention?
4. What is the current meter/system status?
5. What action should I take?
6. What information is operationally significant?

The visual system must support the user rather than compete with
the data.
