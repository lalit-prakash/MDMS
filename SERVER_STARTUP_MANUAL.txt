MDMS — MANUAL SERVER STARTUP GUIDE
====================================

This is for running the backend and frontend yourself, outside of Claude Code's
preview tooling (e.g. in your own terminal, or after a machine restart).

Repo root: C:\Users\lalit\OneDrive\Desktop\MDMS\mdms_repo


PREREQUISITES (one-time)
-------------------------
1. .NET 8 SDK installed.
2. Node.js (v20+) and npm installed.
3. PostgreSQL running locally, with a database named "mdms".
4. Point the backend at your real Postgres password (see below) — the
   appsettings.json value is a placeholder and will NOT work as-is.


SET YOUR POSTGRES PASSWORD (one-time)
----------------------------------------
backend/MDMS.Api/appsettings.json ships with a placeholder connection string
(Password=CHANGE_ME) that cannot work on your machine — it must be replaced
with YOUR actual local Postgres password. Do this once via .NET user-secrets
(keeps it out of the file, never committed to git):

    cd C:\Users\lalit\OneDrive\Desktop\MDMS\mdms_repo\backend\MDMS.Api
    dotnet user-secrets set "ConnectionStrings:Mdms" "Host=localhost;Port=5432;Database=mdms;Username=postgres;Password=REPLACE_THIS_PART_ONLY"

IMPORTANT: In that command, replace ONLY the text "REPLACE_THIS_PART_ONLY"
with your real Postgres password — type it in yourself. Do not paste this
line verbatim: nobody else knows your password, so no example command in
this file (or given to you by anyone else) can ever contain the real value
for you. If you don't know your Postgres password, see "COMMON PROBLEMS"
below for how to check/reset it.

Verify it took effect:
    dotnet user-secrets list
    (should print ConnectionStrings:Mdms = Host=...;Password=<your real password>,
    not CHANGE_ME or a placeholder)


1. START THE BACKEND API
-------------------------
Open a terminal:

    cd C:\Users\lalit\OneDrive\Desktop\MDMS\mdms_repo\backend
    dotnet run --project MDMS.Api --urls http://localhost:5004

What this does automatically (Development environment only):
  - Applies any pending EF Core migrations to your local Postgres database.
  - Enables Swagger UI at http://localhost:5004/swagger
  - Enables a permissive CORS policy for http://localhost:3000 (the frontend).

Wait for this line before continuing:
    Now listening on: http://localhost:5004

Verify it's healthy (in a second terminal, or a browser tab):
    curl http://localhost:5004/health
    -> should return: {"status":"Healthy"}

Leave this terminal running. Press Ctrl+C in it to stop the API.


2. START THE FRONTEND (Next.js dev server)
--------------------------------------------
Open a second terminal:

    cd C:\Users\lalit\OneDrive\Desktop\MDMS\mdms_repo\frontend
    npm install        (only needed the first time, or after pulling dependency changes)
    npm run dev

Wait for:
    Local:  http://localhost:3000

Open http://localhost:3000 in your browser.

Leave this terminal running. Press Ctrl+C in it to stop the frontend.


3. SIGNING IN
--------------
There is no seeded default account. To get in the first time:

  a) If no user exists at all, create one via the API directly (Swagger UI at
     http://localhost:5004/swagger, under UsersController -> POST /api/v1/users
     — note this endpoint requires an Admin-authenticated caller once at least
     one Admin account already exists; the very first account in a brand new
     database can be inserted directly via Swagger only while no auth
     middleware blocks it, or by a developer inserting a row directly).

  b) Once a username exists in the Users module, go to
     http://localhost:3000/login and click "First time signing in? Claim your
     account" — enter that username and choose a password. This calls
     POST /api/v1/auth/claim, which only works once per account (before it has
     a password set).

  c) After that, sign in normally with that username/password at /login.

4. MOBILE APP (Flutter, Android)
----------------------------------
The mobile/ folder is the consumer Flutter app. It talks to the same backend
API from step 1 — no separate server, but it does need the backend reachable
from the phone.

ONE-TIME SETUP (Flutter + Android SDK)
This machine did not have Flutter or a full Android SDK installed, so this
session set both up from scratch under your user profile (not Program Files,
so no admin rights were needed):

  Flutter SDK:  C:\Users\lalit\flutter          (cloned from the Flutter GitHub repo, stable channel)
  Android SDK:  C:\Users\lalit\Android\Sdk      (cmdline-tools + platform-tools + platforms
                                                   34/35/36 + build-tools installed via sdkmanager)

Neither is on PATH permanently yet. Every command below assumes you add them
to PATH for that terminal session first:

    (PowerShell)
    $env:PATH = "C:\Users\lalit\flutter\bin;C:\Users\lalit\Android\Sdk\platform-tools;$env:PATH"

If you want this permanent, add those two paths to your user PATH environment
variable via Windows Settings -> Environment Variables, then restart your
terminal.

Verify the toolchain:
    flutter doctor -v
  It's fine if "Visual Studio" and "Chrome" checks show issues — this project
  only targets Android. The line to watch for is:
    [√] Android toolchain - develop for Android devices (Android SDK version ...)

CONNECT YOUR PHONE
  1. On the phone: Settings -> About phone -> tap "Build number" 7 times to
     enable Developer options, then Settings -> Developer options -> turn on
     "USB debugging".
  2. Plug the phone into this PC via USB.
  3. Run:  adb devices
     The phone should show as "device" (not "unauthorized" — if it shows
     unauthorized, unlock the phone screen and tap Allow on the popup; if no
     popup appears, run `adb kill-server` then `adb devices` again to force a
     fresh pairing prompt).

REACH THE BACKEND FROM THE PHONE
  The app is hardcoded to call http://localhost:5004 (see
  mobile/lib/core/api_client.dart). For a real device connected over USB,
  "localhost" only resolves correctly if you forward the phone's localhost
  port to this PC's:

      adb reverse tcp:5004 tcp:5004

  Re-run this after every reboot/reconnect (it doesn't persist). Skip this
  step entirely if you're using an emulator instead of a real device —
  Android emulators already reach the host machine at 10.0.2.2, which the
  app's network security config also allows.

5. STOPPING EVERYTHING
------------------------
Press Ctrl+C in each terminal window (backend and frontend separately).

If a backend process gets orphaned (e.g. a terminal was closed without
Ctrl+C) and port 5004 is already in use on your next `dotnet run`, find and
stop it first. In PowerShell:

    Get-Process MDMS.Api -ErrorAction SilentlyContinue | Stop-Process -Force

Then re-run step 1.


6. COMMON PROBLEMS
--------------------
"Port 5004 already in use"
  -> Another MDMS.Api process is still running. See step 4 above.

"Port 3000 already in use"
  -> Another Next.js dev server is still running. Stop it (Ctrl+C in its
     terminal, or `Get-Process node | Stop-Process -Force` as a last resort —
     this kills ALL Node processes, so prefer closing the specific terminal).

Frontend loads but every page shows "could not reach the backend API"
  -> The backend (step 1) isn't running, or isn't reachable at
     http://localhost:5004. Check its terminal for errors, and that
     Postgres itself is running.

Backend crashes on startup with:
  "Npgsql.PostgresException: 28P01: password authentication failed for
   user 'postgres'"
  -> Your Postgres password hasn't been set correctly. See "SET YOUR
     POSTGRES PASSWORD" above. If you don't know your password:
       - Try the password you chose when installing PostgreSQL, or the
         one in pgAdmin's saved connection (pgAdmin -> right-click your
         server -> Properties -> Connection, though it won't show the
         password itself, just confirm the server/user).
       - To reset it outright, open pgAdmin (or psql as an OS admin) and run:
             ALTER USER postgres WITH PASSWORD 'a-new-password-you-choose';
         then use that new password in the user-secrets command above.

"npm : File ...\npm.ps1 cannot be loaded because running scripts is
disabled on this system" (PowerShell only)
  -> One-time PowerShell setting, unrelated to this project:
         Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
     Answer "Y" when prompted, then re-run npm install/npm run dev normally.
     (Or use `npm.cmd install` / `npm.cmd run dev` to sidestep it entirely.)

"MSB3021/MSB3027: Could not copy ... The file is locked by another process"
  -> A previous `dotnet run` (backend) is still running somewhere and
     holding its own build output locked. Find and stop it first:
         Get-Process dotnet -ErrorAction SilentlyContinue | Stop-Process -Force
     (This stops ALL dotnet processes, backend included — safe to do
     before re-running `dotnet build` or `dotnet run`.)

Login says "No MDMS user account found with that username"
  -> That username doesn't exist in the Users module yet. See step 3.

"This account already has a password set. Use Sign in instead."
  -> You already claimed this account previously; use the normal Sign In
     form instead of "Claim your account".

adb shows the phone as "unauthorized"
  -> Unlock the phone (the trust dialog only shows on an unlocked screen),
     then run `adb kill-server` followed by `adb devices` to force a fresh
     pairing dialog, and tap Allow (tick "Always allow from this computer").

App installs but every screen shows "No internet connection"
  -> You likely skipped `adb reverse tcp:5004 tcp:5004` (see section 4), or
     the backend (step 1) isn't running. This forwarding does not persist
     across reboots/reconnects — re-run it each session.

`adb install` fails with "INSTALL_FAILED_USER_RESTRICTED: Install canceled
by user"
  -> Android showed an install-confirmation popup on the phone and it was
     dismissed. Check the phone and tap Install, then re-run the adb install
     command.

Stale-looking frontend after pulling new code / switching branches
  -> Stop the frontend (Ctrl+C), delete the .next folder, then `npm run dev`
     again:
         cd C:\Users\lalit\OneDrive\Desktop\MDMS\mdms_repo\frontend
         rmdir /s /q .next          (Command Prompt)
         Remove-Item -Recurse -Force .next   (PowerShell)
         npm run dev
